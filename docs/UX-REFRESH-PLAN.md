# 念头盒 NianBox · UX 升级执行基准

## 产品目标
把念头盒从分散的功能集合整理成一条容易理解的路径：记下来 → 收件箱管理 → AI 整理/创作 → 有价值的念头升级为项目。保留现有暖纸白、灵感紫和温润克制的品牌视觉，不以换肤替代体验改进。

## 必须遵守
- 不破坏已有数据结构、历史记录、关联关系和备份兼容性。
- 不将未完成的同步描述成已同步；任何状态都必须来自真实执行结果。
- 不把模型名、接口地址、令牌、内部队列和后台诊断暴露给普通用户。
- 不在首次记录前要求登录、填写标题、分类或标签。
- 所有操作必须有真实结果、加载/错误状态和可理解的恢复路径。
- 优先移动端与窄屏，兼容桌面端、iOS Safari 与微信内置浏览器。
- 分支开发、测试、预览验证后再合并，不直接覆盖线上主分支。

## 信息架构
1. **记念头**：只承担快速输入和保存。保存后给出轻量的下一步提示；不要让生图、AI 整理、分类等并列操作争夺主按钮。
2. **收件箱**：所有念头的统一管理入口；搜索、分类、置顶、状态、编辑和删除在这里保持一致。
3. **念头详情**：完整原文的唯一权威来源。AI 整理、生图/分享等相关动作集中在清晰的操作区；项目通过关联来源返回原念头。
4. **项目**：从念头升级后的推进空间，突出目标、状态、下一步行动；补充信息折叠。不得把项目详情做成重复的收件箱编辑页。
5. **我的作品**：集中查看、保存和分享已创作的图片；避免在首页、列表和项目详情重复铺开生图入口。
6. **设置**：一级只保留账户与同步、通用设置、帮助与意见反馈、关于念头盒。备份与恢复、隐私说明、危险操作放二级页面；开发诊断仅限显式开启的开发者入口。
7. **应用封面**：品牌标志、产品名、简短价值主张和一个进入按钮。仅首次访问展示；再次访问不应重复阻挡用户。链接进入时可有短暂过渡，但不能影响哈希路由、返回行为或数据初始化。

## 视觉规范
- 保留现有品牌色 token：暖纸白背景、近白卡片、墨色正文、灵感紫主操作、柔和辅助色。
- 统一页面标题、正文/辅助说明层级、按钮高度、卡片边框、圆角、间距、空状态和提示。
- 减少多层嵌套卡片、冗长解释、重复边框和并列主按钮。
- 关键动作必须清楚；次要选项可折叠，但不能隐藏用户完成任务所必需的信息。
- 不以装饰性动效掩盖信息架构问题；动画轻量、可访问、可减少动态效果。

## 云端同步验收
逐项验证新增、编辑、删除/回收、恢复、置顶、分类、项目与念头关联、断网恢复、多设备登录、重复记录与冲突。用户界面只表达「已同步 / 正在同步 / 同步未完成」及必要解释；不能仅凭登录成功就宣称数据一致。明确哪些数据目前不支持云同步（例如仅存本机的作品图片），不得误导。

## 实施顺序
- P0：检查现有实现与数据边界，保留原功能；移除重复入口，统一主要用户路径。
- P1：重整首页、念头详情、项目详情和设置的信息层级。
- P2：加入轻量应用封面与安全的进入过渡。
- P3：专项排查云同步完整性与错误恢复。
- P4：执行 typecheck、单测、生产构建、站点集成检查，并在手机与桌面预览中逐条回归。

## 当前进展
- 已在独立分支 `feat/nianbox-ux-refresh` 开始工作。
- 首页：已移除输入区重复的「一键生成图片」快捷入口，保留 AI 整理作为可选下一步；保存成功后的操作仍保留直接生图入口，避免打断刚记录完的用户。
- 项目详情：当前进度与产品形态保留为常用字段；目标用户、核心功能、仓库和发布网址已收进「补充信息（可选）」折叠区，降低首次打开的表单压力。
- 设置：已将隐私说明、备份与恢复、危险操作等高级数据管理区域收进「隐私、备份与数据管理」折叠区；账户与同步、当前数据、意见反馈和帮助改进仍保持直接可见。
- 自动化测试首次失败的根因是原测试仍要求首页显示旧的生图入口。已更新对应测试以验证新的交互原则：首屏不重复显示生图按钮，保存成功后仍可进入生图页。正在等待新的 CI 结果。
